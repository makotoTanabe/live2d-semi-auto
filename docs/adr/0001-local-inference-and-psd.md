# Local proposals, generated pixels, and PSD export

Status: accepted for the user's requested automatic separation / AI repair / PSD development milestone.

The manual editing slice remains available without GPU, neural weights, or external services. Automatic separation initially uses deterministic Lab color clustering to produce editable color regions; it does not label semantic face/eye/hair parts or infer anatomical occlusions. All nontransparent pixels belong to exactly one proposal, so accepting them into an empty project can reconstruct the original. Proposals are added, never used to erase existing manual parts.

AI repair uses an optional, CPU TorchScript LaMa adapter behind an `InpaintingBackend` protocol. The roughly 196 MiB checkpoint is fetched only through an explicit command, outside the checkout. It is verified against a pinned SHA-256 before loading. The pin was established from the upstream IOPaint-linked artifact after checking its published MD5 (`e3aa4aaa15225a33ec84f9f4bc47e500`). No artwork is uploaded and no model is downloaded during package installation, import, or application startup. Telea is also available as a traditional image-processing alternative and is labeled as non-AI.

Each part has separate visible, requested hidden, generated pixel, and generated provenance arrays. Visible source pixels always take priority. A repair request overlapping the part's visible mask is rejected. The result is compared with the current layer and requires explicit acceptance; regeneration can replace selected hidden pixels while retaining other accepted repairs. Undo/redo shares immutable generated arrays. Schema 2 records assets and operation metadata, including model checksum and the crop/resize/padding transform, while loading schema 1 remains supported.

LaMa receives a crop with a 64 px context margin. Crops larger than 512 px are scaled down with the mapping recorded, and input is padded to multiples of 8. Output is restored into canvas coordinates and only target pixels are adopted. This bounds CPU work but limits fine detail for large regions. The neural model predicts plausible fill; it cannot verify unseen character anatomy.

`psd-tools` is isolated in an exporter adapter. PSDs use RGB color mode, 8 bit channels, sRGB ICC metadata, independent normal-blend pixel layers, Unicode names, transparency channels, and an explicit merged-transparency tag. Original-profile pixels are converted to sRGB for PSD only. There are no layer masks or background layer. Atomic publication to a new filename prevents overwriting user data. The current tests reopen PSDs and inspect layer order, pixels, visibility, ICC profile, and merged transparency. Cubism desktop import has not been tested; compatibility must not be declared complete until that check is performed.

GUI inference and PNG/PSD export use worker threads. Inference cancellation discards the result when the backend returns; it does not interrupt the underlying Torch kernel. Export is not cancellable once started, to keep file publication consistent. Editing is disabled during a job while the event loop remains responsive. Project save/load still run synchronously.
