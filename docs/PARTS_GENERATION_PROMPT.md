# 最初からパーツ素材を生成する場合

新しいキャラクターをAIで描く用途では、隠れた領域まで描いた部品を最初から用意すると、1枚の完成絵から分けるより作業を減らせます。既存のイラストをそのまま素材化する用途では、完成絵から分割する経路も引き続き必要です。

キャラクターの見本シートは、完成図・表情例・ポーズ例・拡大された目や口が混ざりやすく、そのままの切り出しだけではLive2D素材になりません。同じキャラクターの部品でも、縮尺・角度・描き方・隠れ領域・配置座標の整合を確認する必要があります。

## 全身完成図と分割パーツを1枚にまとめるプロンプト

元の指定に合わせ、左に全身完成図、右に枠で整理した分割パーツ・表情見本・ポーズ見本を配置します。左の基本ポーズを全パーツの縮尺と形状の基準にします。以前の9部品サンプルは部品のみを生成した実験で、その画像と実際に使ったプロンプトは履歴として残します。

```text
参考画像のキャラクターをベースに、Live2D用の分割パーツを整理したイラストを作成してください。
髪型、顔立ち、衣装、アクセサリー、配色、頭身、線の太さ、塗りを参考画像に合わせてください。
必ず1枚の画像に、全身完成イラストと分割パーツ配置図をまとめてください。

【配置】
左側：頭から靴まで切れない、正面向きの全身完成イラスト。基本ポーズ・基本表情。
右側：顔・髪・体・アクセサリーの部品を、四角い枠で区切って見やすく並べる。
右側の別の見本欄：表情差分とポーズ差分の完成見本をまとめる。
背景は白または実際に透明な背景。市松模様を背景として描かないでください。
枠線や部品名は部品から離し、各部品の周囲に十分な余白を確保してください。

【縮尺と整合】
左の基本ポーズの全身完成図を、右のすべての基本パーツの共通基準にしてください。
基本パーツは、左の完成図から取り外して移動したときと同じ縮尺（1:1）で描いてください。
肩幅、顔幅、目の間隔、髪の長さ、胴体、腕、手、脚、靴の寸法比を左の完成図と揃えてください。
枠に収めるために部品だけを拡大・縮小したり、縦横比・角度・パースを変えたりしないでください。
部品が収まらない場合は枠やシートを大きくし、部品自体の大きさは保ってください。
口の差分と開き手・握り手も、同じ顔・同じ手に差し替えられる大きさにしてください。
左右はキャラクター本人を基準にしてください。正面図では画面の左右と逆になります。

【顔パーツ】
顔の輪郭ベース：正面向き。目・眉・鼻・口・頬の赤らみは付けず、耳と髪に隠れる額も描く。
目：左右別。眉：左右別。鼻。口：基本・笑顔・怒り・泣き・驚き・照れに対応する独立差分。
頬の赤らみ：左右別の独立パーツ。

【髪パーツ】
前髪、後ろ髪、左右のサイド髪、必要な毛束。
顔や前髪で隠れる部分も描き、髪型のシルエットを左の完成図に合わせる。

【体パーツ】
上半身の服、下半身の服、首・胴体、左右の腕、左右の手（開き・握り）、左右の脚、左右の靴。
袖、襟、リボン、エプロンなど、重なる衣装部品は必要に応じて独立させる。
肩や腕の付け根、服の重なりで隠れる範囲も連続して描き、部品を動かしても穴が出にくくする。

【その他】
参考画像にあるヘッドドレス、髪飾り、リボン、ボタンなどのアクセサリーを独立パーツにする。
白い衣装や白目は不透明な白として残す。

【表情見本】
笑顔、怒り顔、泣き顔、驚き顔、照れ顔。
左の基本顔と同じ顔の形・髪型・顔パーツの配置を保ち、表情に必要な部品だけ変える。

【ポーズ見本】
正面を向いた基本ポーズ、片手を上げて挨拶するポーズ、腕を組んだポーズ。
すべて同じキャラクターの頭身、手足の長さ、服装と配色を保つ。
表情・ポーズの完成見本は基本パーツの枠と明確に分ける。
見本を縮小する場合は見本欄だけに共通の縮尺を用い、基本パーツの縮尺は変えない。

できる限り高解像度で描き、細いまつげや小さな口の差分が潰れないようにしてください。
```

同じ縮尺を指定しても、生成モデルがピクセル単位の一致を守る保証はありません。生成後に左の完成図へ再配置し、頭身、肩幅、顔パーツの位置、輪郭や隠れ領域を検査してください。透明なPNGであることも実際に確認してください。白背景を一括で透明化すると、白い衣装や白目も失われることがあります。

枠と見出しはシートを読むための情報です。部品の切り出しには含めず、表情・ポーズの完成見本も部品として重ねないでください。目をさらに白目・虹彩・まつげへ細分化する場合も、左の完成図における寸法を共通基準にします。

## 実際のLive2D素材へ揃える条件

- 切り出した部品の名前・ID・元シート上の領域を記録する。
- 完成図のキャンバスに合わせて、各部品の縮尺・回転・配置を確認し、変換情報を記録する。
- より扱いやすい生成方法は、完成図の位置とキャンバス寸法を指定し、1部品ずつ同一キャンバスの透明PNGへ出力する方法。プロンプトだけで位置が厳密に揃う保証はないため、再合成で検査する。
- 部品を動かして、額、髪の付け根、肩などに欠けた領域がないか確認する。

アプリでは、1枚の完成絵をマスクで分ける経路に加えて、完成図とパーツシートを対にした位置合わせ経路を用意しています。シートから切り出した部品は原画と同じキャンバス寸法の独立レイヤーへ配置します。元画像の画素を分割したパーツと、シートから明示的に追加したパーツは別の由来として保存します。

## AIによる位置合わせの構成

完成図と部品シートを対にして入力し、GPTに部品名・シート上の切り出し範囲・対応する基準点を推定させます。基準点は目の両端、髪の先端、肩など、形状上対応する離れた2〜8点を使用します。画像処理で同一倍率の拡大縮小・回転・移動を最小二乗で計算し、全パーツを完成図と同じキャンバスの透明PNGへ配置します。鏡映、縦横で異なる倍率、パース補正、変形は行いません。

変換は非破壊に保存し、元シート・切り出した元部品・抽出マスク・基準点・変換行列・拡大率・回転・移動を残します。GPTの信頼度と注意事項、基準点の残差も保存します。再合成と完成図の差分を見て、対応が間違った部品やずれを確認してください。信頼度や小さな残差は、正しい対応やLive2D素材の完成を保証しません。

この流れではGPTが対応と基準点の推定を担当し、ローカル画像処理が切り出し・配置・出力を担当します。位置合わせ自体は画像を生成しません。形状の違いや欠けを描き直す処理は含まないため、必要な領域の補完や元シートの作り直しは別工程です。

## アプリでの手順

1. 1枚のシートから左の基本ポーズの完成図だけを、枠や見出しを入れずに別の画像へ切り出します。右側の素材欄も別の画像へ切り出します。どちらも切り出し時には拡大・縮小せず、元シートを保持します。現行アプリには完成図と素材欄を自動で別ファイルにする機能はありません。
2. 切り出した完成図を「画像を読み込む」で開き、「GPTでシートを位置合わせ（外部送信）」で素材欄の画像を選びます。シートは1枚で生成し、アプリへ渡す段階で完成図と素材を分けます。
3. 透明背景は `alpha`、白背景を除去する場合は `white` を選び、利用できる画像認識・構造化JSON対応モデルを指定します。
4. 完成図とシートをOpenAI APIへ送信する確認に同意すると、位置合わせ候補を取得します。APIキーは環境変数から渡し、画像送信にはAPI利用枠が必要です。
5. 原画・候補の再合成・差分を見て採用を判断します。採用すると既存の手動パーツを残して候補を追加します。既存パーツとの重複で見た目が変わる場合は、表示状態や順序を調整してください。
6. 採用した部品を選び、「選択パーツの位置合わせを調整」で移動量・倍率・角度を修正します。元の切り出し画像から再描画し、マスクの手動編集も保持します。補完領域を追加した部品は位置調整できないため、先に位置合わせを済ませてください。
7. パーツを隠す・動かすなどして隠れ領域を確認し、必要なら補完を行います。`.l2split` に保存し、PNGまたはPSDへ出力します。Cubism実機でのPSD読み込みは未検証です。

完成図とシートは、同じICCプロファイルを持つ画像、または両方ともプロファイルが付いていない画像を使用してください。プロファイルが異なる場合は送信前に停止します。元ファイルを残し、両方を同じsRGBプロファイルで別名出力してから読み込んでください。位置調整は元部品から求めた固定の中心を基準とし、画像と手動編集マスクを元の基準データから変換するため、繰り返し回転による劣化やずれを抑えます。キャンバス外へはみ出す部品は警告が出るため、切れていないか確認してください。

`white` は切り出し画像の外周に接続した白に近い領域だけを除去します。白い部品が外周に触れていると一緒に除去される場合があり、囲まれた背景が残る場合もあります。透過PNGの方が安定します。シートの装飾・文字・別ポーズ・隣の部品が範囲内に混ざると、その画素も切り出されるためプレビューで確認してください。

## 再現可能なサンプル生成

```bash
uv run --locked python scripts/create_alignment_sample.py \
  --source samples/original_character.png \
  --atlas samples/parts_atlas.png \
  --background alpha \
  --model gpt-5.6-luna \
  --upload \
  --output /path/to/new_alignment_result
```

APIキーは注入された環境変数または非表示入力で渡します。コマンド引数や保存データには含めません。モデル名は自身のAPIプロジェクトで利用可能なものに変更できます。実行すると元シート、API応答、マスク、編集可能なプロジェクト、透過PNG、PSD、再合成・差分・カバレッジ画像、検証レポートを新しい出力先に保存します。保存済み応答は `--upload` の代わりに `--response /path/to/response.json` を指定してオフラインで再現できます。`--response-log /path/to/new_response.json` を追加すると、候補の検証で拒否された場合もAPI応答を新しいファイルへ残せます。レポートの差分やカバレッジは検査の補助であり、目・髪・衣装の意味的な分離品質は人間が判断してください。

## 実際に作成したサンプル

[samples/parts_atlas.png](../samples/parts_atlas.png) は、完成絵を参照して新たに生成した透明背景の9部品シートです。実際のGPTリクエストで部品対応と基準点を取得し、[再合成の比較](../samples/results/alignment/comparison.png)、[独立レイヤー一覧](../samples/results/alignment/isolated_layers.png)、[検証レポート](../samples/results/alignment/report.json)、プロジェクト・PNG・PSDを保存しました。位置合わせには画像生成を使わず、シートの画素を変換しています。

このサンプルは手直しが必要な候補です。完成絵との形状差、輪郭の粗さ、胴体の切れや腕の不足があり、大きな部品の基準点残差は約21〜43pxです。前髪とヘッドバンドの切り出し範囲にはキャンバス外へのはみ出し警告もあります。データの保存・再読込とPSD各レイヤーの画素保持を確認していますが、これだけで素材の完成やCubism互換性を判断しないでください。
