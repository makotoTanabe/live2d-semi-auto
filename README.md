# Live2D Web Studio

キャラクター画像を編集可能なパーツへ分け、ブラウザーで表情とモーションを設定し、Webアプリへ組み込める動く2Dキャラクターとして出力するツールです。

Webエディターでは、まばたき、口開閉、視線、顔向き、呼吸、髪の揺れをプレビューできます。出力は透過PNG、`model.json`、再生用JavaScript、動作例HTMLを含むZIPで、エディターサーバーから独立して再生できます。描画はCanvas2Dのメッシュ変形とグループ変換で行います。

## Webエディターの起動

Python 3.12以上と [uv](https://docs.astral.sh/uv/) を使用します。

```bash
uv sync --locked --extra web
uv run --locked --extra web live2d-semi-auto-web
```

ブラウザーで **http://127.0.0.1:8080** を開いてください。ホスト・ポートは `--host`、`--port` で変更できます。開発中のエディターはローカル／私有環境向けです。公開ホスティング・認証基盤は含みません。書き出したキャラクターは任意のWebサイトへ配置できます。

クラウド環境では、必要に応じて次のキャッシュ・仮想環境を使用します。

```bash
export UV_CACHE_DIR=/workspace/.cache/uv
export UV_PROJECT_ENVIRONMENT=/workspace/.venvs/live2d-semi-auto
export XDG_CACHE_HOME=/workspace/.cache
```

## キャラクターを作って動かす

1. 「サンプルを動かす」で配置済みの9パーツを試します。APIキーは不要です。自身の素材は「画像を開く」または「プロジェクトを開く」から読み込みます。
2. 左のパーツ一覧で名前・種類・表示・順序を編集し、「動きの役割」を顔・目・口・髪・胴体などへ割り当てます。役割はパーツIDに結び付き、名前を変えても維持します。
3. 中央のプレビューで再生し、右側の表情、モーション、顔向き、目・口・呼吸を調整します。自動まばたき、自然な動き、マウス追従を切り替えられます。
4. 「マスク編集」表示でブラシ／投げ縄の追加・消去を行います。ホイールで拡大、中ボタンで移動、Undo/Redoで修正できます。原画・選択パーツ・再合成・差分も確認できます。
5. 「保存」で編集可能な `.l2split` をダウンロードします。パーツと役割・支点・動作の強さ・メッシュ設定を含み、後で読み込んで再開できます。表情選択やライブのスライダー値はプレビュー用で、すべてを保存する形式ではありません。
6. 「Web用モデルを書き出す」でZIPをダウンロードし、展開先を静的HTTPサーバーで配信して `index.html` を開きます。ローカルファイルの読み込みを許可するブラウザーでは直接開く方法も使えます。自身のページへの組み込みは [docs/WEB.md](docs/WEB.md) の例を使用してください。

表情は通常・笑顔・怒り・泣き・驚き・照れ、モーションは待機・うなずき・首振り・挨拶を用意しています。目や口などの素材がない場合、その部位の動きは制限されます。動作中に欠けや境界を確認し、素材・マスク・役割を修正してください。

Web版の制作機能、API設定、サーバーと書き出しモデルの違いは [docs/WEB.md](docs/WEB.md) を参照してください。

Web版では1アップロード32MiB、画像の縦横4096px、128パーツ、保存する画像・マスクの合計 `64 × 1024²` 画素を上限とします。上限を超える候補や編集操作は既存の作業を保ったままエラーになります。候補数を減らすか、元ファイルを残して小さい画像を読み込んでください。

## 任意のデスクトップ版

従来のPySide6版は `uv run --locked live2d-semi-auto` で起動します。ローカルのデスクトップ画面が必要です。プロジェクト形式とコアの編集・推論・出力処理はWeb版と共通です。以下のボタン名・ショートカットはデスクトップ版の操作です。

1. 「画像を読み込む」でPNG・JPEG・WebPを開き、「パーツを追加」を押します。
2. 名前・種類・表示状態を設定し、「属性を適用」を押します。
3. 「マスク編集・オーバーレイ」でブラシ／なげなわの追加・消去を選び、左ドラッグで編集します。半径は原画のピクセル単位です。
4. ホイールで拡大縮小、中ボタンドラッグで移動します。「全体表示」は `Ctrl+0` です。
5. 「選択パーツ」「再合成」「差分」「原画」で結果を確認します。リストの下ほど手前のレイヤーです。マスク濃度を0にするとオーバーレイが消えます。
6. `Ctrl+S` で `.l2split` に保存し、`Ctrl+O` で再開します。原画とマスクを含むため、元画像が移動しても再開できます。
7. 「PNG出力」で親フォルダーと**新しい**出力フォルダー名を指定します。透過PNG、`manifest.json`、`preview.png` が作られます。既存の出力には上書きしません。

Undoは `Ctrl+Z`、Redoは `Ctrl+Shift+Z` です。パーツ作成・削除・属性・順序変更・マスク編集を取り消せます。履歴はセッション内の直近50操作です。

「不透明領域のマスク候補」は非透明画素を選択するローカルの簡易バックエンドです。確認ダイアログで採用するまで編集状態は変わりません。背景を含む不透明画像では全画像が候補になります。髪・顔などの分類には、下記のGPT候補機能を選択してください。

## 自動分割・補完・任意の素材出力

新しいキャラクターを最初から部品で生成したい場合は、[パーツ生成用のプロンプトと位置合わせの手順](docs/PARTS_GENERATION_PROMPT.md) を参照してください。完成絵とパーツシートを対にして、GPTの基準点候補から共通キャンバスへ配置できます。

- 「自動パーツ分割（色領域）」で候補数を指定します。色の近い画素をまとめた候補をプレビューし、採用すると新しいパーツとして追加します。背景も含めて元画像を再構成できる分割です。既存の手動パーツは消しません。髪・目・顔の意味的な分類や隠れ領域の自動推定は行いません。
- 「GPTでパーツ候補（外部送信）」はGPTの画像認識でパーツの分類・位置を提案し、ローカルのGrabCutでマスク候補にします。外部送信の確認と候補採用の確認を別々に行います。正確な輪郭や隠れ形状を保証する機能ではありません。API設定は [docs/MODELS.md](docs/MODELS.md) を参照してください。
- 「GPTでシートを位置合わせ（外部送信）」でパーツシート、背景の扱い、利用するモデルを指定します。完成絵とシートの送信を確認すると、GPTが切り出し範囲と対応する基準点を提案し、ローカルで拡大縮小・回転・移動を計算します。原画・再合成・差分をプレビューしてから採用します。元シートと切り出し画像を保持し、既存パーツへ追加します。
- 採用したシートのパーツは「選択パーツの位置合わせを調整」で移動量・倍率・角度を修正できます。Undo/Redoが可能で、繰り返し調整しても元の切り出し画像と手動編集マスクの基準データから描画します。補完前に位置合わせを済ませてください。白背景の除去は切り出し外周に接続した白に近い領域の推定であり、白い衣装なども消える場合があります。透過PNGを推奨します。完成絵とシートのカラープロファイルが異なる場合は、元画像を残して両方を同じsRGBプロファイルで別名出力してください。
- マスク編集の対象を「補完領域」に切り替え、**選択パーツの可視マスクの外側**に隠れ領域を描きます。「隠れ領域を補完」からLaMa（AI）またはTelea（画像処理）を選択します。現在のレイヤーと候補を比較してから採用でき、Undoも可能です。可視画素は生成結果で上書きしません。
- LaMaには明示的なモデル取得とオプション依存が必要です。[docs/MODELS.md](docs/MODELS.md) の手順を実行してください。起動・インストール時にモデルは自動取得しません。
- 「PSD出力」（`Ctrl+Shift+E`）はRGB・8bit・sRGBの独立した透過レイヤーを新しい `.psd` ファイルへ保存します。レイヤー名・順序・表示状態を保持し、レイヤーマスクを使用しません。特定の外部アプリとの互換性はそこでの読み込み確認後に判断します。Web版でも「素材を書き出す」からPNG・PSDを取得できます。
- 推論とPNG/PSD出力はバックグラウンドで実行します。推論中の「結果を破棄」は、計算が戻った時点で候補を捨てます。実行中のモデル計算自体は中断しません。

空マスクは作業途中の保存には使用できますが、PNG出力ではエラーになります。名前の重複、キャンバスの不一致なども検出します。

## テスト・サンプル

Ubuntuの画面がない環境でQtのテストを実行する場合は、`sudo apt-get install libegl1` でOS側のEGLライブラリを用意してください。`QT_QPA_PLATFORM=offscreen` の場合も、PySide6の読み込みにこの共有ライブラリが必要です。CIでは明示的にインストールし、Qt起動を確認してからテストを実行します。

```bash
QT_QPA_PLATFORM=offscreen uv run --locked --extra web pytest -q
```

デスクトップGUIテストは画面のない環境でも実行します。小さな合成画像でコア処理を検証し、[samples/original_character.png](samples/original_character.png) でも保存・再合成・PNG出力を確認します。このピンク髪のサンプルはAIで生成したオリジナルキャラクターです。出典は [samples/README.md](samples/README.md) を参照してください。実ブラウザーでの編集・アニメーション・独立した書き出しモデルの検証手順は [docs/WEB.md](docs/WEB.md) に記載しています。

今回の検証はPython 185件成功、Chromium 15チェック成功、Web API経由の実LaMa補完10チェック成功です。[検証記録](samples/results/web/verification.json)、[再生動画](samples/results/web/character_motion.webm)、[組み込み用モデルZIP](samples/results/web/character-web.zip) を収録しています。`file://` の直接再生チェック1件はブラウザーの管理ポリシーによる遮断としてスキップし、独立HTTP配信での再生と画面サイズ変更を確認しています。

Web版のブラウザー検証レポート・画面・動画・書き出しモデルは [samples/results/web](samples/results/web) に保存しています。エディターから独立したHTTP配信での再生を確認しました。このクラウドのChromiumでは管理ポリシーが `file://` を拒否するため、直接ファイルを開く確認はスキップしています。

[samples/results](samples/results) に自動分割マスク、分割プレビュー、補完前後の画像、生成領域マスク、編集可能な `.l2split`、透過PNG一式、PSD、検証レポートを収録しています。生成スクリプトは `scripts/create_samples.py` です。実モデルのテストは `LAMA_MODEL_PATH` が未設定ならスキップされます。

GPT位置合わせは、生成した [パーツシート](samples/parts_atlas.png) と完成絵を実際に `gpt-5.6-luna` へ送り、9パーツを配置しました。[比較画像](samples/results/alignment/comparison.png)、[独立レイヤー一覧](samples/results/alignment/isolated_layers.png)、[検証レポート](samples/results/alignment/report.json) を確認できます。元シートの保存、プロジェクトの再読込、PSDの独立レイヤー画素を検証済みです。この素材には形状差・輪郭の粗さ・胴体の切れ・腕の不足があり、大きな部品には約21〜43pxの基準点残差が残ります。動作を付けても不足部分は自動で描き足されません。アニメーションの動作確認と、素材自体の仕上がりは別に確認してください。再現スクリプトは `scripts/create_alignment_sample.py` です。

## 範囲と設計

- 原画と読み込んだシートを上書きしません。GPT機能は明示確認後に画像をOpenAI APIへ送信します。他の処理はローカルです。GPUは不要です。ローカルAI補完には別途モデルが必要です。
- シートの位置合わせは同一倍率・回転・移動に対応します。部品ごとの形状差、パース差、欠けは自動で描き直しません。分類・配置・前後関係を人間が確認し、必要な補完を別工程で行います。
- PNG素材出力は原画と同じキャンバス寸法で原画のICCプロファイルを保持します。WebモデルはsRGBの透過画像を切り出し、元座標を設定ファイルへ保持します。PSDもsRGBへ変換します。
- UIとコア、保存処理、推論バックエンドを分離しています。[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) に座標系・保存形式・制限を記載しています。
- 製品仕様は [docs/SPEC.md](docs/SPEC.md)、実装ルールは [AGENTS.md](AGENTS.md) を参照してください。

## プロジェクトの目標

キャラクター画像からパーツ候補を作成し、マスク・前後関係・役割を人間が修正し、ブラウザーで表情とモーションを設定して、Webアプリへ組み込めるモデルを出力します。原画と再合成の比較、プロジェクトの保存・再開を重視します。

汎用タイムライン制作、複雑な物理演算、VTube Studio向け完成モデルは対象外です。AI推論・Web描画・出力はコアから分離し、バックエンドを交換できる構成です。
